= 仮想マシンの高度な管理

== はじめに

Legacy Systems Inc. は事業拡大を続けており、重要な仮想マシンをホストするために、複数のデータセンターとパブリッククラウドリージョンに OpenShift Virtualization を導入しています。AWS、IBM Cloud、Google Cloud などのさまざまなクラウドプロバイダーで仮想化クラスタをホストする可能性があるため、チームは既存のインフラストラクチャとアプリケーションの稼働を維持しながら、新しいプラットフォームへの投資とトレーニングのバランスを取る必要があります。これらの異なる仮想マシンワークロードの管理は、統一されたアプローチがなければますます複雑になる可能性があります。そこで Red Hat Advanced Cluster Management for Kubernetes の出番です。RHACM を単一のインターフェースとして使用し、すべての仮想ワークロードを、その場所に関係なく管理することが、大規模な分散仮想化環境を運用する上で重要です。このモジュールでは、RHACM で稼働中のクラスタを検出する方法、RHACM を使用して仮想ワークロードを視覚化する方法、そして仮想マシンをリモートからクラスタにデプロイする方法を説明します。

[[discover_cluster]]
== クラスターの検出

NOTE: このラボのセクションでは、共有 ACM ハブクラスターを使用します。コンソール URL はラボ監督者から提供されます。ワークステーション インターフェースにログインすると、ユーザー アカウント（user1 - user**n**）が割り当てられます。このユーザーでログインし、このラボを完了してください。

. ラボ ユーザー アカウントに割り当てられた認証情報を使用して、共有 Red Hat Advanced Cluster Managment (RHACM) ハブのコンソールにログインします。
+
image::module-05-virt-acm/00-openshift_login.png[title="OpenShift Login", link=self, window=blank, width=100%]
+
. 初めてログインすると、管理対象のクラスターが存在しないことがわかります。*Import cluster* ボタンをクリックしてください。
+
image::module-05-virt-acm/01-import_cluster.png[title="Import Cluster", link=self, window=blank, width=100%]
+
NOTE: 他のラボ参加者がこのステップをすでに通過している場合、ページの内容が上記のスクリーンショットと完全には一致しない可能性があります。その場合でも、上部にある *Import Cluster* ボタンをクリックしてクラスターをインポートし、ラボを続行できます。
+
image::module-05-virt-acm/01a-import_cluster_alt.png[title="Import Cluster Alt", link=self, window=blank, width=100%]
+
. 次の画面は、*Import an existing cluster* ウィザードの *Details* ページです。このページのフィールドに以下の値を入力してください。
+
* *Name:* `userX-virt-cluster`
* *Cluster set:* legacy-systems-inc
* *Import mode:* 既存のクラスターのサーバーURLとAPIトークンを入力します
+
image::module-05-virt-acm/02-import_cluster_details.png[title="Import Cluster Details", link=self, window=blank, width=100%]
+
. *Import mode* を選択し、ドロップダウンから Enter your server URL adn API token for the existing cluster を選ぶと、クラスターを検出するための *Server URL* と *API Token* の入力を求められます。クラスターを検出するには、元のクラスターからこれらの値を取得する必要があります。
. 元のラボクラスターを開いたタブに戻り、上部の *admin* ユーザーをクリックして、ドロップダウンメニューから *Copy login command* オプションを選択します。

+
image::module-05-virt-acm/03-copy_login_command.png[title="Copy Login Command", link=self, window=blank, width=100%]
+
. 新しいタブが開き、htpass_provider 認証エージェントを介してクラスターに再度ログインするよう求められます。クラスター管理者の認証情報は以下の通りです。
+
* *User:* `{openshift_cluster_admin_username}`
* *Password:* `{openshift_cluster_admin_password}`
+
. ログインすると、大きな白い画面に *Display Token* というリンクが表示されます。それをクリックしてください。
+
image::module-05-virt-acm/04-display_token.png[title="Display Token", link=self, window=blank, width=100%]
+
. これをクリックすると、*API Token* と *Server URL* の値の両方を含む CLI 認証コマンドを示すページが表示されます。
+
image::module-05-virt-acm/05-display_api_token_server_url.png[title="Display API Token, Server URL", link=self, window=blank, width=100%]
+
. これらの値をそれぞれコピーし、*Import an existing cluster* ウィザードの *Details* ページのそれぞれのフィールドに貼り付けます。右側の *eye* ボタンをクリックすると *API Token* が表示され、正しくコピーされたことを確認できます。準備ができたら、*Next* ボタンをクリックしてください。
+
image::module-05-virt-acm/06-paste_api_token_server_url.png[title="Paste API Token, Server URL", link=self, window=blank, width=100%]
+
. ウィザードの次のページは *Automation* ページで、Ansible Automation Platform を使用して自動化テンプレートを設定し、マルチクラスタ環境で様々なクラスタ管理タスクを実行できます。これらの操作は現在このワークショップの範囲外ですので、*Next* ボタンをクリックして続行してください。
+
image::module-05-virt-acm/07-auto_template.png[title="Automation Page", link=self, window=blank, width=100%]
+
. ウィザードの最後のページは *Review* ページで、入力した情報を確認できます。準備ができたら、*Import* ボタンをクリックしてください。
+
image::module-05-virt-acm/08-import_cluster_review.png[title="Import Cluster Review", link=self, window=blank, width=100%]
+
. プロセスが開始され、クラスターがインポートを開始することを示す短いポップアップが表示されます。プロセスはかなり速く進むはずですが、同時にインポートを試行するユーザーの数によって影響を受ける可能性があります。
+
image::module-05-virt-acm/09-import_in_progress.png[title="Import In Progress", link=self, window=blank, width=100%]
+
. クラスターのインポート プロセスが完了すると、クラスターのステータスが *Ready* として表示され、クラスターの *Infrastructure* タイプ、現在サブスクライブされているソフトウェア *Channel*、*Cluster set*、コンソールを直接開くためのリンク、クラスターの説明に使用される *Labels* のリストなど、クラスターに関する大量の情報が表示されます。
+
image::module-05-virt-acm/10-import_complete.png[title="Import Complete", link=self, window=blank, width=100%]

[[explore_cluster]]
== 管理対象クラスタリソースの探索

クラスターが見つかったので、複数のクラスターを管理する際に Red Hat Advanced Cluster Managment for Kubernetes (RHACM) を使用するとどのような利点が得られるかを見てみましょう。

. *Nodes* タブをクリックすると、クラスター内の物理ノードのリストと現在のステータスが表示されます。ノード自体をクリックすると、より詳細な情報が表示されます。マネージドクラスター内の *worker node 3* をクリックして、実際に試してみてください。

+
image::module-05-virt-acm/11-node_list.png[title="Node List", link=self, window=blank, width=100%]
+
. モジュール 1 で確認したように、新しいタブが起動し、管理対象クラスターのノード ページが表示されます。
+
image::module-05-virt-acm/12-node_3_details.png[title="Node 3 Details", link=self, window=blank, width=100%]
+
. このウィンドウを閉じて、ページ上部の *Grafana* リンクをクリックすることで、マネージドクラスタで収集されたグラフを見ることができます。リンクをクリックしてください。
+
image::module-05-virt-acm/13-grafana_link.png[title="Grafana Link", link=self, window=blank, width=100%]
+
. OpenShiftの認証情報を使用してログインするよう求められます。*Log in with OpenShift* ボタンをクリックしてください。
+
image::module-05-virt-acm/14-log_in_grafana.png[title="Grafana Login", link=self, window=blank, width=100%]
+
. OpenShift ログインが表示されるので、関連付けられている *UserX* アカウントとそのパスワードを使用してログインする必要があります。
+
image::module-05-virt-acm/00-openshift_login.png[title="OpenShift Login", link=self, window=blank, width=100%]
+
. *ACM - Clusters Overview* ダッシュボードが表示され、管理されているラボ環境内のすべてのクラスターに関する基本情報が表示されます。
+
NOTE: この段階に到達するタイミングによっては、グラフにデータが表示されるまでに少し時間がかかる場合があります。
+
image::module-05-virt-acm/15-default_grafana_dashboards.png[title="Default Grafana Dashboards", link=self, window=blank, width=100%]
+
. *All Dashboards* ボタンをクリックし、 *Executive dashboards / Single Cluster View* のダッシュボードを選択すると、RHACM がクラスターの仮想マシンの展開に関する情報を一元的に表示する方法を確認できます。
+
image::module-05-virt-acm/16-virt_cluster_view.png[title="Virt Cluster View", link=self, window=blank, width=100%]
+
. 単一クラスター ビューの上部パネルには、仮想ゲストの合計数、現在のステータス、各 VM によって報告されたオペレーティング システムの内訳など、クラスター上の仮想マシンのワークロードに関する多くの便利な情報が表示されます。
+
image::module-05-virt-acm/17-single_cluster_top.png[title="Single Cluster Top", link=self, window=blank, width=100%]
+
. 単一クラスタービューの下半分は、複数の折りたたみ可能なパネルで構成されており、ワーカーノードとクラスター内の仮想マシンのリソース使用率に関する重要な情報が表示されます。*CPU Utilization* をクリックして展開し、詳細を確認してください。また、隅にあるドロップダウンメニューから、収集された統計情報の期間をリセットすることもできます。
+
image::module-05-virt-acm/18-single_cluster_bottom.png[title="Single Cluster Bottom", link=self, window=blank, width=100%]
+
. 単一クラスタービューの確認が終わったら、そのタブを閉じてください。
. これで *ACM - Clusters Overview* ページに戻り、もう一度 *All Dashboards* ボタンを選択して、今度は *Executive dashboards / Clusters Overview*  を選択すると、マルチクラスター全体のビューが表示されます。
+
image::module-05-virt-acm/19-multi_cluster_view.png[title="Multi Cluster View", link=self, window=blank, width=100%]
+
. このダッシュボードには、各クラスターの情報、利用可能なノードの総数、仮想マシンの総数、そして各クラスター全体の仮想マシンのステータスが表示されます。また、警告、ゲストOSの概要、リソース使用率もこれまでと同様に表示されますが、表示範囲はより拡大されています。
+
image::module-05-virt-acm/20-multi_cluster_dashboard.png[title="Multi Cluster Dashboard", link=self, window=blank, width=100%]

マルチクラスター環境全体で仮想資産の状態を観察する方法がわかったので、それをどのように管理できるかを見てみましょう。

NOTE: Grafanaを起動したタブを閉じて、RHACMコンソールに戻ることができます。

[[manage_vms]]
== RHACM から VM を管理する

. 左側のメニューから、*Infrastructure* をクリックし、次に *Virtual machines* をクリックします。
+
image::module-05-virt-acm/21-infrastructure-vms.png[title="Left Side Menu", link=self, window=blank, width=100%]
+
. RHACM が現在認識できるすべての仮想マシンの一覧ページが表示されます。
. 表示される列は、*Name*、*Cluster*、*ネームスペース*、または *Node* で特定の仮想マシンを並べ替えたり識別したりするのに役立ちます。
. 列の一覧は完全にカスタマイズ可能で、ページに表示されるマシンの数もカスタマイズ可能です。
+
image::module-05-virt-acm/22-virtual_machine_list.png[title="Virtual Machine List", link=self, window=blank, width=100%]
+
. *Launch links* ボタンを使用すると、仮想マシンの詳細ページ、仮想マシン コンソール、または Observability メトリックのいずれかへの新しいタブを開くショートカット リンクが提供されます。これらはすべて 1 つの簡単なアクセス ポイントからアクセスできます。
+
image::module-05-virt-acm/23-launch_links.png[title="Launch Links", link=self, window=blank, width=100%]
+
. *Launch links* から *Virtual machine details* リンクをクリックすると、新しいタブで仮想マシン管理が開きますが、多数の仮想マシンを素早く操作する必要がある場合は、RHACM から直接操作する方がはるかに便利です。
. 各仮想マシンの右側にある 3 点メニューをクリックすると、まさにそれが実行できます。表示されるリストは、*Virtual machine details* ページに表示されるアクション リストとほぼ同じです。
. このメニューを使用して、仮想マシンの停止/起動/再起動、スナップショットの作成、または YAML 経由でマシンの定義の編集を行うことができます。
+
image::module-05-virt-acm/24-vm_management.png[title="Virtual Machine Management", link=self, window=blank, width=100%]

== まとめ

このモジュールでは、Red Hat Advanced Cluster Managment for Kubernetes (RHACM) を使用して仮想化ワークロードを検出、監視、管理する方法を学びました。このモジュールの内容は、マルチクラスタ OpenShift Virtualization 環境で RHACM が実現できることのほんの一部に過ぎません。前述のように、Ansible Automation を活用することで複数のクラスタにまたがる自動アクションを実行できます。また、GitOps などの強力なツールを活用することで、VM セットをデプロイし、仮想環境全体でクラスタ構成の同期を維持できます。
